## 1. Introduction

Building an app is not always a smooth process. Sometimes, the app does not work as expected. This is normal.

Think about building a bookshelf. If you put a panel in the wrong place, you do not throw the bookshelf away. You check the instructions, find the mistake, and fix it.

App development works in the same way.

When something goes wrong, compare what you wanted with what the app actually did. Then explain the problem to the AI model and ask it to make a fix.

This process is called **debugging**.

## 2. What Is Debugging?

Debugging means finding and fixing problems in an app.

A simple debugging process:

1. Test the app.
2. Find something that is not working.
3. Compare the expected result with the actual result.
4. Explain the problem to the AI model.
5. Ask the model to fix it.
6. Test the app again.

You do not always need to understand the code to explain a problem clearly.

## 3. What Is Iteration?

**Iteration** means repeating a process to make something better.

In app development, it means:

- Build the app.
- Test the app.
- Find problems.
- Fix the problems.
- Test again.
- Improve the app.

Almost every app needs this process.

As you repeat these steps, you also become better at writing prompts and guiding AI.

## 4. What You Will Learn

This section focuses on four important skills.

### A. Debug Your App

Learn how to understand an error, find a problem, and identify what needs to change.

### B. Communicate Clearly with AI

Explain the difference between what you wanted and what the app actually did.

Give the AI enough information to understand the problem.

### C. Create Rules That Always Work

You can add rules that the app should follow every time.

For example:

- Every storyboard must end with a Call to Action (CTA).
- Every report must include a summary.
- Every form must check required fields.

These rules help make the app more consistent.

### D. Stress-Test Your App

Stress-testing means testing your app with difficult, unusual, or incorrect inputs.

For example:

- Leave required fields empty.
- Enter very long text.
- Use incorrect data.
- Try unexpected inputs.
- Test different user actions.

This helps you find problems before real users find them.

## 5. Example: Storyboard Visualizer App

In the course video, Ammaar tests an app called **Storyboard Visualizer**.

The app takes a video advertisement idea and turns it into a storyboard.

The storyboard has three columns:

| Column | Purpose |
|---|---|
| Visuals | Shows what viewers will see |
| Audio and Dialogue | Shows voice, sound, and dialogue |
| Shot Type and Duration | Shows the camera shot and its length |

During testing, Ammaar finds different problems.

### Common Problems

**1. Quota Error**

The app may stop working because it reaches a usage limit.

**2. Hallucination**

Sometimes, an AI model gives incorrect information or makes assumptions that are not true.

This is called a hallucination.

**3. Missing Rules**

The generated storyboard may not follow the team's video guidelines.

For example, a shot may be too long or the video may use the wrong tone.

### Using Context Documents

Ammaar uses a document called *Video Guidelines*.

It contains the team's rules for video advertisements, such as:

- Voice and tone
- Video pacing
- Shot duration
- Other creative standards

The app uses this document as extra context when creating a storyboard.

A context document is helpful, but it is not required for every app.

## 6. What Is a CTA?

CTA means **Call to Action**.

It is a message that tells people what to do next.

Examples:

- Get started for free.
- Sign up today.
- Learn more.
- Download the app.

Ammaar adds a rule that every storyboard must end with a CTA.

This is an example of a rule that the app should follow every time.

## 7. Cybersecurity Example: Testing an Incident Response App

Imagine you are building a cybersecurity incident response app.

The app helps users create reports about security incidents.

During testing, you find these problems:

| Problem | Possible Fix |
|---|---|
| The report has no incident date | Add a required date field |
| The app accepts empty descriptions | Add input validation |
| The report shows incorrect information | Review the AI instructions and source data |
| The app gives an error with long text | Test and improve text handling |
| Important incident details are missing | Add a rule for required report fields |

You can explain each problem to the AI and ask it to fix the issue.

Then test the app again.

**Important:** This is a learning example. Always check AI-generated security reports against the original evidence.

## 8. Useful Prompt for Debugging

You can use this prompt when testing your own AI-generated app:

```text
Act as an experienced app tester.

I have tested my app and found a problem.

Expected result:
[Describe what should happen]

Actual result:
[Describe what happened]

Please:
1. Identify the possible cause.
2. Explain the problem in simple English.
3. Fix the issue.
4. Keep all existing features.
5. Do not change unrelated parts of the app.
6. Tell me how to test the fix.

Also, check if this problem can happen again.
```

## 9. Key Notes

- Debugging means finding and fixing problems.
- App failures are a normal part of development.
- Iteration means testing and improving again and again.
- Clear instructions help AI understand problems.
- Guardrails help an app follow important rules.
- Stress-testing helps find problems before real users do.
- You can improve your prompting and problem-solving skills through practice.

A good app is not always built in the first attempt. Test it, find the problems, fix them, and keep improving.
